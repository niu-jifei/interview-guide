

## 前端启动部署

### 1. 启用 Corepack（包管理器代理）

Corepack 是 Node.js 16.13+ 引入的工具，用于统一管理包管理器版本。

```bash
# 启用 Corepack（首次使用需要执行）
corepack enable
```

**作用：**
- 使 `yarn`、`pnpm` 等命令通过 Corepack 执行
- 自动读取项目 `package.json` 中的 `packageManager` 字段
- 确保所有开发者使用相同版本的包管理器

### 2. 项目包管理器配置

项目在 `package.json` 中指定了精确的 pnpm 版本：

```json
{
  "packageManager": "pnpm@10.26.2+sha512.0e308ff2005fc7410366f154f625f6631ab2b16b1d2e70238444dd6ae9d630a8482d92a451144debc492416896ed16f7b114a86ec68b8404b2443869e68ffda6"
}
```

**字段解析：**
- `pnpm` - 包管理器名称
- `10.26.2` - 版本号
- `sha512.0e308ff...` - 校验和（验证下载完整性，确保安全）

### 3. 前端启动部署规范

#### 3.1 开发环境启动

```bash
# 步骤 1：进入前端目录
cd frontend

# 步骤 2：安装依赖（首次或依赖变更时）
pnpm install

# 步骤 3：启动开发服务器
pnpm dev
```

**开发服务器特性：**
- **按需编译**：浏览器请求时才编译对应模块，无需等待全量编译
- **即时启动**：Vite 开发服务器秒级启动
- **热更新（HMR）**：修改代码后自动更新，无需刷新页面
- **TypeScript 转译**：使用 esbuild 快速转译 TS → JS（仅移除类型注解，不检查类型）
- **访问地址**：通常为 `http://localhost:5173`（具体端口见终端输出）

#### 3.2 生产构建

```bash
# 步骤 1：执行生产构建
pnpm build
```

**构建流程：**
1. `tsc` - TypeScript 类型检查，确保代码无类型错误
2. `vite build` - 全量编译 + 打包优化
   - 代码分割（按路由/模块拆分）
   - 压缩 JS/CSS
   - Tree-shaking（移除未使用代码）
   - 输出到 `dist/` 目录

**构建产物示例：**
```
dist/
├── index.html
└── assets/
    ├── index-abc123.js     # 45.67 kB │ gzip: 15.23 kB
    └── index-def456.css    # 12.34 kB │ gzip:  3.45 kB
```

#### 3.3 预览生产构建

```bash
# 构建完成后，本地预览验证
pnpm preview
```

- **访问地址**：`http://localhost:4173`
- **用途**：模拟生产环境，验证构建结果是否正确
- **注意**：此命令使用 `dist/` 目录的静态文件，不会重新编译

#### 3.4 部署到服务器

```bash
# 步骤 1：确保构建成功
pnpm build

# 步骤 2：将 dist/ 目录部署到 Web 服务器
# 例如：Nginx、Apache、Vercel、Netlify 等
cp -r dist/* /var/www/html/
```

### 4. 命令速查表

| 命令 | 说明 | 使用场景 |
|------|------|----------|
| `pnpm dev` | 启动开发服务器 | 日常开发调试 |
| `pnpm build` | 类型检查 + 生产打包 | 提交代码前、部署前 |
| `pnpm preview` | 预览生产构建 | 部署前验证 |
| `pnpm install` | 安装项目依赖 | 首次克隆项目、依赖更新 |

### 6. 常见问题

**Q: 需要先编译再运行吗？**
A: 不需要。`pnpm dev` 直接启动 Vite 开发服务器，Vite 会按需编译模块。

**Q: `pnpm dev` 和 `pnpm run dev` 有区别吗？**
A: 没有区别，`pnpm dev` 是简写形式，两者等价。

**Q: 为什么开发模式比构建模式快？**
A: 开发模式使用按需编译 + esbuild 转译，构建模式需要全量编译 + 优化打包。

**Q: TypeScript 类型错误会影响开发吗？**
A: 不会。`pnpm dev` 只做转译，不检查类型。类型错误由 IDE 提示，`pnpm build` 时才会阻止编译。
